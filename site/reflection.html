Stage 1

What everything is

Reflection is reading and using a class's metadata while the program runs. When the JVM loads Payment.class, it keeps a description of it in memory (Metaspace). Every item below is a piece of that description.

Object svc = c.getDeclaredConstructor(PaymentRepository.class).newInstance(repo);

for (Field f : c.getDeclaredFields())  System.out.println(f.getName());
for (Method m : c.getDeclaredMethods()) System.out.println(m);

Stage 2

How everything connects

Reflection on its own is a set of read and call APIs. It becomes useful when a framework connects it to annotations and proxies.

The chain in one line

ClassLoader loads Class → Class declares Fields / Methods / Constructors → they carry Annotations → a framework reads the annotations → builds objects with Constructor.newInstance, wraps them in a Proxy → the proxy runs extra logic and calls your code with Method.invoke.

Stage 3

How it happens

Five procedures. Steps marked reflection are where java.lang.reflect is actually called.

W1 · Payment service starts up

  1. Scan. Spring reads class files under org.example with ASM (bytecode reading, no class loading yet) and finds @Service, @RestController, @Repository.
  2. Define. Each match becomes a BeanDefinition: class name, scope, dependencies.
  3. Pick a constructor. Spring inspects constructors and their parameter types.reflection
  4. Create. Constructor.newInstance(paymentRepository) builds PaymentServiceImpl.reflection
  5. Post-process. BeanPostProcessors scan methods for @Transactional, @PreAuthorize, @Async.reflection
  6. Proxy. If any matched, Spring generates PaymentServiceImpl$$SpringCGLIB$$0 and registers that instead of your object.
  7. Map routes. MVC stores every @PostMapping Method object in a route table.reflection
  8. Ready. All metadata is cached. Requests reuse it.

W2 · POST /payments hits port 8081

  1. Filter chain. BearerTokenAuthenticationFilter validates the JWT and stores the Authentication. No reflection.
  2. Route. DispatcherServlet finds the cached HandlerMethod for POST /payments.
  3. Bind body. Jackson creates PaymentRequest and fills its fields from JSON.reflection
  4. Invoke controller. InvocableHandlerMethod.doInvoke calls your controller with Method.invoke.reflection
  5. Hit the proxy. Controller calls the service. The call lands on the CGLIB proxy, not your class.
  6. Security check. The interceptor reads @PreAuthorize and evaluates it against the JWT scopes. Fail → AccessDeniedException → 403.reflection
  7. Transaction. TransactionInterceptor opens a transaction, then calls your real method.
  8. Save. Hibernate reads Payment's fields and writes the row.reflection
  9. Respond. Jackson calls PaymentResponse getters to write JSON.reflection

W3 · Inside Method.invoke

  1. Access check. Is the method accessible from the caller? If not and not setAccessible → IllegalAccessException.
  2. Argument check. Count and types; primitives are unboxed. Mismatch → IllegalArgumentException.
  3. Dispatch. Since JDK 18 (JEP 416) the call goes through a MethodHandle, which the JIT can optimise.
  4. Wrap errors. Anything the target throws is wrapped in InvocationTargetException. Spring unwraps it for you.

W4 · Hibernate loads a Payment

  1. Query. findByIdAndOwner runs SQL; a row comes back.
  2. Instantiate. Hibernate calls Payment's no-arg constructor. This is why JPA needs one.reflection
  3. Fill. Column values are written into private fields (field access, because @Id is on a field).reflection
  4. Lazy links. Lazy associations become generated subclasses. This is why entities should not be final.

W5 · Proxy call and self-invocation

  1. Outside call. Controller → proxy → interceptors (security, transaction, your aspect) → target method.
  2. Inside call. Target calls this.otherMethod(). this is the real object, so the proxy is skipped.
  3. Result. @Transactional, @PreAuthorize and your trace on otherMethod do nothing. Fix: move it to another bean.

Prod · 1. Startup guard (fail fast)

@Bean
ApplicationRunner securityGuard(RequestMappingHandlerMapping mapping) {
    return args -> mapping.getHandlerMethods().forEach((route, handler) -> {
        if (handler.getBeanType().getName().startsWith("org.example")
                && !handler.hasMethodAnnotation(PreAuthorize.class))
            throw new IllegalStateException("Unsecured endpoint: " + route);
    });
}

Prod · 2. @Sensitive masking with a cache

@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.FIELD)
public @interface Sensitive {}

public final class Masker {
    private static final Map<Class<?>, List<Field>> CACHE = new ConcurrentHashMap<>();

    public static String describe(Object o) {
        List<Field> fields = CACHE.computeIfAbsent(o.getClass(), c ->
            Arrays.stream(c.getDeclaredFields())
                  .filter(f -> !Modifier.isStatic(f.getModifiers()))
                  .peek(f -> f.setAccessible(true)).toList());   // reflection once per class
        StringJoiner out = new StringJoiner(", ", o.getClass().getSimpleName() + "[", "]");
        for (Field f : fields) {
            try {
                Object v = f.get(o);
                String s = f.isAnnotationPresent(Sensitive.class) && v != null
                         ? "****" + String.valueOf(v).substring(Math.max(0, String.valueOf(v).length() - 4))
                         : String.valueOf(v);
                out.add(f.getName() + "=" + s);
            } catch (IllegalAccessException e) { out.add(f.getName() + "=?"); }
        }
        return out.toString();
    }
}
// use: log.info("created {}", Masker.describe(payment));

When everything goes wrong: layered defence

  1. Compile. Prefer typed code. Reflection only inside frameworks or one small utility.
  2. CI. ArchUnit rules, 401/403 tests, masking tests. Fail the build, not production.
  3. Startup. Guard runner refuses to start with an unsecured endpoint. Bad deploys never take traffic.
  4. Runtime. Metrics, traces, audit log. You see the problem before customers report it.
  5. Incident. Trace ID → Zipkin span → log level via Actuator → fix → add a test so it never repeats.

Stage 6

Interview answers

Say them out loud. Each is about 30 seconds and tied to SecurePay.

The 60-second story

"In SecurePay, a Spring Boot payment system with an authorization server, gateway, payment and notification services, reflection drives most of what the framework does: dependency injection, route mapping, @PreAuthorize checks, JPA mapping and JSON binding. I used it deliberately in two places: a dev-only report that prints the app's blueprint, and production guardrails, a startup check that refuses to boot if a payment endpoint lacks @PreAuthorize, plus annotation-based masking of account numbers. Because Jackson binds fields by reflection, I take the payment owner from the JWT, never from the request body."
What is reflection?

The ability of Java code to inspect and use classes, fields, methods, constructors and annotations at runtime, through java.lang.Class and java.lang.reflect. It reads the metadata the JVM keeps for every loaded class.

Where does Spring use it?

Creating beans through constructors, calling @Bean methods, building the MVC route table from @RequestMapping, reading @PreAuthorize and @Transactional to build proxies, and invoking controller methods. Hibernate and Jackson use it to fill fields.

What are the downsides?

Errors move to runtime, it bypasses encapsulation, it's harder to refactor because names are strings, and uncached lookups are slow. That's why I keep it in frameworks and cache lookups at startup.

getMethods vs getDeclaredMethods?

getMethods returns public methods including inherited ones. getDeclaredMethods returns every method declared in that class, any visibility, but not inherited ones.

How do you access a private field, and is that a security problem?

getDeclaredField, setAccessible(true), then get or set. It shows that private is not a security boundary. Secrets belong in a vault, and on Java 9+ the module system can block it.

What is InvocationTargetException?

The wrapper Method.invoke throws when the called method itself fails. The real exception is getCause(). Logging only the wrapper hides the root cause.

Why doesn't @Transactional or @PreAuthorize work on self-invocation?

Spring adds that behaviour through a proxy around the bean. A call from inside the same object uses this, which is the target, so it never passes through the proxy. I move the method to another bean.

JDK dynamic proxy vs CGLIB?

JDK proxy implements interfaces at runtime; Spring Data uses it for repositories. CGLIB generates a subclass, so it works on classes but not final classes or final methods. Spring Boot defaults to CGLIB for AOP.

Why does a JPA entity need a no-arg constructor?

Hibernate creates the object first through reflection, then fills fields from the row. It can't guess constructor arguments. It also subclasses entities for lazy loading, so they shouldn't be final.

Reflection vs annotations?

Annotations are passive labels. Reflection is how code reads them at runtime, and only if they have RetentionPolicy.RUNTIME.

Is reflection slow?

The lookup is the expensive part. Frameworks look up once at startup and cache the Method objects. Since JDK 18 invoke runs on method handles, which the JIT optimises well. In a hot path I cache or use MethodHandle.

How does reflection relate to security in your project?

Three ways: @PreAuthorize is enforced by reading the annotation; mass assignment is a risk because Jackson binds by reflection, so the owner comes from the JWT; and I never let user input choose a class or method name.

Reflection vs debugging vs tracing?

Reflection is the program reading its own structure at runtime. Debugging is a developer pausing it to inspect state. Tracing records a request's path across services in every environment. I use all three, for different questions.
